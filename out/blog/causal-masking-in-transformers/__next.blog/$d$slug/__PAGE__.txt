4:T49fa,<p>In a Transformer's attention layer, a token can attend to every other token in the sequence — including the ones that come after it. Causal masking removes that. It makes each token attend only to itself and the tokens before it, <strong>never to future tokens</strong>.</p>
<h2 id="why-it-is-needed"><a class="heading-anchor" href="#why-it-is-needed">Why it is needed</a></h2>
<p>Take the sentence <code>The kettle boiled over</code>, four tokens:</p>

























<table><thead><tr><th>position</th><th>token</th></tr></thead><tbody><tr><td>1</td><td><code>The</code></td></tr><tr><td>2</td><td><code>kettle</code></td></tr><tr><td>3</td><td><code>boiled</code></td></tr><tr><td>4</td><td><code>over</code></td></tr></tbody></table>
<p>A language model is trained to predict the next token. At position 2 it should predict <code>kettle</code> having seen only <code>The</code>.</p>
<p>Without masking, position 2 can also attend to <code>boiled</code> and <code>over</code>. Now the task is trivial — something that boiled over is very likely a kettle, and the model can read that straight off the input instead of predicting it.</p>
<p>This is information leakage. The model learns to lean on tokens it is supposed to be predicting, training loss looks excellent, and then generation falls apart, because at generation time those future tokens do not exist yet.</p>
<h2 id="the-mask"><a class="heading-anchor" href="#the-mask">The mask</a></h2>
<p>The fix is a mask matrix the same shape as the attention score matrix. A <code>1</code> allows attention, a <code>0</code> blocks it. It comes out lower-triangular:</p>

<h2 id="worked-example"><a class="heading-anchor" href="#worked-example">Worked example</a></h2>
<p>Take the row for <code>kettle</code> — its raw attention scores against all four tokens:</p>



















<table><thead><tr><th></th><th><code>The</code></th><th><code>kettle</code></th><th><code>boiled</code></th><th><code>over</code></th></tr></thead><tbody><tr><td>scores</td><td>1.1</td><td>2.5</td><td>1.0</td><td>0.3</td></tr></tbody></table>
<p>Run softmax on that row <strong>without</strong> masking:</p>



















<table><thead><tr><th></th><th><code>The</code></th><th><code>kettle</code></th><th><code>boiled</code></th><th><code>over</code></th></tr></thead><tbody><tr><td>weights</td><td>0.16</td><td>0.63</td><td><strong>0.14</strong></td><td><strong>0.07</strong></td></tr></tbody></table>
<p><code>kettle</code> is putting 14% of its attention on <code>boiled</code> and 7% on <code>over</code>. That is 21% of its attention spent on the future — the leak, in numbers.</p>
<p>Now apply the mask. Positions 3 and 4 are set to −∞:</p>



















<table><thead><tr><th></th><th><code>The</code></th><th><code>kettle</code></th><th><code>boiled</code></th><th><code>over</code></th></tr></thead><tbody><tr><td>masked scores</td><td>1.1</td><td>2.5</td><td>−∞</td><td>−∞</td></tr></tbody></table>
<p>And softmax again:</p>



















<table><thead><tr><th></th><th><code>The</code></th><th><code>kettle</code></th><th><code>boiled</code></th><th><code>over</code></th></tr></thead><tbody><tr><td>weights</td><td>0.20</td><td>0.80</td><td><strong>0.00</strong></td><td><strong>0.00</strong></td></tr></tbody></table>
<p>The future gets exactly zero. The 21% that was leaking redistributes over <code>The</code> and <code>kettle</code>, and the row still sums to 1.</p>

<p>The mask also has to be applied to the scores, before the softmax. Zeroing the weights afterwards does not work either — the future tokens have already contributed to the denominator, so the surviving weights no longer sum to 1.</p>
<h2 id="attention-sinks"><a class="heading-anchor" href="#attention-sinks">Attention sinks</a></h2>
<p>One thing worth noticing in the masked row: <code>The</code> still gets a 0.20 share, even though it carries almost no meaning here.</p>
<p>This is common. Across models, nearly every position sends some attention to the first token, and the pattern has a name — <strong>attention sinks</strong>. The first token acts as somewhere for attention to go when a head has nothing in particular to attend to.</p>
<p>It matters in practice. Methods that drop old tokens to save memory have to keep the first few, or quality collapses.</p>
<h2 id="summary"><a class="heading-anchor" href="#summary">Summary</a></h2>
<ul>
<li>Causal masking limits each token to itself and the tokens before it.</li>
<li>Without it, the model attends to tokens it is meant to predict — information leakage.</li>
<li>The mask is lower-triangular: <code>1</code> on and below the diagonal, <code>0</code> above.</li>
<li>Masked positions are set to −∞ <em>before</em> the softmax, so they come out as exactly 0.</li>
<li>Setting them to 0 instead does not work, because <span class="katex"><span class="katex-mathml"><math xmlns="http://www.w3.org/1998/Math/MathML"><semantics><mrow><msup><mi>e</mi><mn>0</mn></msup><mo>=</mo><mn>1</mn></mrow><annotation encoding="application/x-tex">e^0 = 1</annotation></semantics></math></span><span class="katex-html" aria-hidden="true"><span class="base"><span class="strut" style="height:0.8141em;"></span><span class="mord"><span class="mord mathnormal">e</span><span class="msupsub"><span class="vlist-t"><span class="vlist-r"><span class="vlist" style="height:0.8141em;"><span style="top:-3.063em;margin-right:0.05em;"><span class="pstrut" style="height:2.7em;"></span><span class="sizing reset-size6 size3 mtight"><span class="mord mtight">0</span></span></span></span></span></span></span></span><span class="mspace" style="margin-right:0.2778em;"></span><span class="mrel">=</span><span class="mspace" style="margin-right:0.2778em;"></span></span><span class="base"><span class="strut" style="height:0.6444em;"></span><span class="mord">1</span></span></span></span>.</li>
