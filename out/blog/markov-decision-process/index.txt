12:T257a,<p>Many decisions do not just earn a reward now; they change what happens next. Running a machine hard earns more today and risks breaking it tomorrow. A Markov decision process (MDP) is the standard mathematical description of that kind of problem, and the foundation of reinforcement learning.</p>
<h2 id="the-five-parts"><a class="heading-anchor" href="#the-five-parts">The five parts</a></h2>
<p>An MDP is defined by:</p>
<ol>
<li><strong>States</strong> — the situations the agent can be in.</li>
<li><strong>Actions</strong> — what the agent can do in each state.</li>
<li><strong>Transitions</strong> — for each state and action, the probability of each next state.</li>
<li><strong>Rewards</strong> — the immediate payoff for taking an action in a state.</li>
<li><strong>A discount factor γ</strong> between 0 and 1 — how much a reward one step later is worth compared with one now.</li>
</ol>
<p>The <strong>Markov</strong> part is an assumption: the next state depends only on the current state and action, not on the history of how you got there. Everything relevant must be captured in the state.</p>
<p>The goal is a <strong>policy</strong> — a rule saying which action to take in each state — that maximises the expected total discounted reward.</p>
<h2 id="a-small-example"><a class="heading-anchor" href="#a-small-example">A small example</a></h2>
<p>A machine can be <strong>cool</strong> or <strong>warm</strong>, or it can <strong>overheat</strong>, which ends everything. Each step you choose to run it <strong>slow</strong> or <strong>fast</strong>:</p>



































<table><thead><tr><th>state</th><th>action</th><th>reward</th><th>what happens next</th></tr></thead><tbody><tr><td>cool</td><td>slow</td><td>+1</td><td>stays cool</td></tr><tr><td>cool</td><td>fast</td><td>+2</td><td>50% stays cool, 50% becomes warm</td></tr><tr><td>warm</td><td>slow</td><td>+1</td><td>50% cools down, 50% stays warm</td></tr><tr><td>warm</td><td>fast</td><td><strong>−10</strong></td><td>overheats — game over</td></tr></tbody></table>
<p>Discount factor γ = 0.9.</p>
<p>Fast is tempting: it pays double. But it heats the machine up, and running fast when warm is a disaster. The right choice in each state depends on its effect on the future.</p>
<h2 id="value-what-a-state-is-worth"><a class="heading-anchor" href="#value-what-a-state-is-worth">Value: what a state is worth</a></h2>
<p>The <strong>value</strong> of a state under a policy is the expected total discounted reward from there on. Two simple policies are easy to evaluate:</p>
<ul>
<li><strong>Always slow:</strong> +1 every step for ever, never at risk. Value <code>1 / (1 − 0.9) =</code> <strong>10</strong> in either state.</li>
<li><strong>Always fast:</strong> from cool, +2 and a coin flip between staying cool and becoming warm — and from warm, −10 and the end. Solving <code>V = 2 + 0.9 × (0.5 V + 0.5 × −10)</code> gives <strong>−4.55</strong>.</li>
</ul>
<p>Greed loses badly. Caution earns a steady 10. Is there anything better?</p>
<h2 id="the-bellman-equation-and-value-iteration"><a class="heading-anchor" href="#the-bellman-equation-and-value-iteration">The Bellman equation and value iteration</a></h2>
<p>The best achievable value satisfies the <strong>Bellman optimality equation</strong>: a state's value is the best, over actions, of the immediate reward plus the discounted expected value of where that action leads:</p>
<p><code>V(s) = max over a of [ R(s, a) + γ × Σ P(s′ | s, a) × V(s′) ]</code></p>
<p><strong>Value iteration</strong> solves it by starting with all values at zero and repeatedly applying the equation:</p>






















































<table><thead><tr><th>iteration</th><th>V(cool)</th><th>V(warm)</th><th>best action when cool</th><th>when warm</th></tr></thead><tbody><tr><td>1</td><td>2.00</td><td>1.00</td><td>fast</td><td>slow</td></tr><tr><td>2</td><td>3.35</td><td>2.35</td><td>fast</td><td>slow</td></tr><tr><td>3</td><td>4.56</td><td>3.56</td><td>fast</td><td>slow</td></tr><tr><td>10</td><td>10.27</td><td>9.27</td><td>fast</td><td>slow</td></tr><tr><td>50</td><td>15.42</td><td>14.42</td><td>fast</td><td>slow</td></tr><tr><td>200</td><td><strong>15.50</strong></td><td><strong>14.50</strong></td><td><strong>fast</strong></td><td><strong>slow</strong></td></tr></tbody></table>
<p>The values converge to 15.5 for cool and 14.5 for warm, and the optimal policy is: <strong>run fast when cool, slow when warm.</strong> It earns the extra reward whenever it is safe and backs off exactly when the risk appears — worth 15.5 against 10 for always-slow and −4.55 for always-fast.</p>

<h2 id="what-the-discount-factor-does"><a class="heading-anchor" href="#what-the-discount-factor-does">What the discount factor does</a></h2>
<p>γ controls how far ahead the agent cares. With γ near 0, only the immediate reward matters and the agent becomes greedy. With γ near 1, distant consequences matter almost as much as immediate ones. In this example a very short-sighted agent would see that fast pays 2 and slow pays 1 everywhere — and run fast when warm, right into the −10.</p>
<h2 id="from-mdps-to-reinforcement-learning"><a class="heading-anchor" href="#from-mdps-to-reinforcement-learning">From MDPs to reinforcement learning</a></h2>
<p>Value iteration needs the transition probabilities and rewards written down. Reinforcement learning tackles the same problem when they are <strong>unknown</strong>: the agent learns by trying actions and observing what happens.</p>
<ul>
<li><strong>Q-learning</strong> learns the value of each state–action pair directly from experience.</li>
<li><strong>Policy gradient methods</strong> — including PPO — adjust a policy's parameters in the direction that increases expected reward.</li>
<li><strong>Deep RL</strong> replaces the table of values with a neural network when there are too many states to list.</li>
</ul>
<p>Language model training with RLHF fits the same frame: the state is the conversation so far, the action is the next token or response, and the reward comes from a learned model of human preferences.</p>
<h2 id="what-to-take-away"><a class="heading-anchor" href="#what-to-take-away">What to take away</a></h2>
<p>A Markov decision process describes sequential decisions with states, actions, transition probabilities, rewards and a discount factor, assuming the current state contains everything relevant. The Bellman equation defines the best value of each state, and value iteration finds it by repeated updates.</p>
<p>In the overheating-machine example, always slow is worth 10 and always fast −4.55, while the optimal policy — fast when cool, slow when warm — is worth 15.5.
