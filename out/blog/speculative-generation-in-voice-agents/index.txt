12:T1ed7,<p>A cascaded voice agent normally works in sequence: wait until it is confident the user has finished, then send the transcript to the language model, then speak. The waiting is the problem. To avoid cutting people off, endpointing has to hold out for a fairly long silence — and the model does nothing during it.</p>
<p>Speculative generation uses that time. As soon as the user <em>might</em> have finished, the agent starts generating a reply from the transcript so far. If the user really has finished, the reply is already under way. If they carry on, the draft is thrown away and the agent tries again at the next pause.</p>
<h2 id="the-saving"><a class="heading-anchor" href="#the-saving">The saving</a></h2>
<p>Suppose the agent's endpointing commits after 500 ms of silence, and the language model needs about 410 ms — first token plus the first sentence — before there is anything to speak.</p>

















<table><thead><tr><th></th><th>reply ready after the user stops</th></tr></thead><tbody><tr><td>wait, then generate</td><td>500 + 410 = <strong>910 ms</strong></td></tr><tr><td>start speculatively at 150 ms of silence</td><td>150 + 410 = <strong>560 ms</strong></td></tr></tbody></table>
<p><strong>350 ms</strong> earlier, on every turn where the guess was right — which is a large share of a voice agent's entire budget. The audio is not played until endpointing actually commits, so the user is never interrupted; the reply is simply ready the moment it is allowed to start.</p>
<p>The expected saving depends on how often the early guess holds:</p>





















<table><thead><tr><th>early guess correct</th><th>average saving per turn</th></tr></thead><tbody><tr><td>60%</td><td>210 ms</td></tr><tr><td>80%</td><td>280 ms</td></tr><tr><td>90%</td><td>315 ms</td></tr></tbody></table>
<h2 id="the-cost-discarded-work"><a class="heading-anchor" href="#the-cost-discarded-work">The cost: discarded work</a></h2>
<p>Every wrong guess is generation that gets thrown away. If a typical turn contains two pauses that look like endings but are not, and each speculative run gets about 20 tokens in before being cancelled, that is 40 discarded tokens per turn — against a reply of around 78. Roughly <strong>half again</strong> as much generation.</p>

<p>How much that matters depends on where the cost lands:</p>
<ul>
<li><strong>Prefill is mostly cached.</strong> Each speculative run shares the long prefix — system prompt and conversation so far — with the previous one. With prompt caching, only the new words of the transcript are processed again.</li>
<li><strong>Decode stops early.</strong> A cancelled run is stopped the moment the user speaks again, so it rarely produces more than a sentence.</li>
<li><strong>Capacity is the real cost.</strong> Under heavy load, speculative runs compete with real ones for GPU time. Systems often speculate less, or not at all, when servers are busy.</li>
</ul>
<h2 id="when-the-transcript-changes"><a class="heading-anchor" href="#when-the-transcript-changes">When the transcript changes</a></h2>
<p>The subtle case is a user who stops, the agent speculates, and the <em>final</em> transcript differs slightly from the partial one used — a word corrected by the recogniser, a last word that arrived late. Two options:</p>
<ol>
<li><strong>Discard and regenerate</strong> whenever the final transcript differs at all. Safe, and gives up the saving on those turns.</li>
<li><strong>Keep the draft if the difference is immaterial</strong> — punctuation, casing, a filler word. Requires a judgement about what "immaterial" means, which is easy to get wrong for numbers and names.</li>
</ol>
<p>Most systems take option 1 for anything beyond trivial differences.</p>
<h2 id="making-the-guesses-better"><a class="heading-anchor" href="#making-the-guesses-better">Making the guesses better</a></h2>
<p>The value of speculation rises with the accuracy of the early guess, so it pairs naturally with better turn detection:</p>
<ul>
<li>A <strong>turn-detection model</strong> that reads the partial transcript can tell "I'd like to book a table for" (clearly unfinished — do not speculate) from "that's all, thanks" (clearly finished — speculate immediately).</li>
<li>Speculate <strong>only above a confidence threshold</strong>, trading a little saving for much less waste.</li>
<li>Allow <strong>more than one speculative run at once</strong> only when capacity is plentiful.</li>
</ul>
<h2 id="speculation-beyond-the-reply"><a class="heading-anchor" href="#speculation-beyond-the-reply">Speculation beyond the reply</a></h2>
<p>The same idea applies to other slow steps. If the user's intent is clear early — "what's my balance" — the agent can start the account lookup before they finish speaking. If they say something else, the result is discarded. Tool calls with no side effects are ideal for this; anything that changes state must never be started speculatively.</p>
<h2 id="what-to-take-away"><a class="heading-anchor" href="#what-to-take-away">What to take away</a></h2>
<p>Speculative generation starts the language model when the user seems to have stopped, and discards the draft if they continue. Starting at 150 ms of silence instead of 500 ms has the reply ready 350 ms sooner on every correct guess — about 280 ms on average at 80% accuracy.</p>
<p>The price is discarded generation, roughly half again as many tokens, softened by prompt caching and early cancellation.
