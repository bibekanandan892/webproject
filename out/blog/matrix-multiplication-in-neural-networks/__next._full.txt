12:T21e3,<p>Open up any neural network — an image classifier, a speech recogniser, a large language model — and nearly all of the computation is the same operation repeated: a matrix multiplication. Attention, feed-forward layers, embeddings, output projections: each is, at its core, inputs multiplied by weights.</p>
<p>Understanding that one operation explains why networks are written the way they are, why GPUs suit them, and why batching requests together makes serving so much cheaper.</p>
<h2 id="one-layer-is-one-multiplication"><a class="heading-anchor" href="#one-layer-is-one-multiplication">One layer is one multiplication</a></h2>
<p>A layer of neurons computes, for each neuron, a weighted sum of all inputs. Write the weights of all the neurons as a matrix and the whole layer becomes a single multiplication:</p>
<p><code>y = x W + b</code></p>
<p>If the input has 3 numbers and the layer has 2 neurons, <code>W</code> is 3 × 2: each column holds one neuron's weights. Feeding two examples at once — a batch — stacks them as rows of <code>X</code>:</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="text" data-theme="github-light github-dark-default"><code data-language="text" data-theme="github-light github-dark-default" style="display: grid;"><span data-line=""><span>X (2×3)        W (3×2)          XW (2×2)</span></span>
<span data-line=""><span>[1 2 3]        [0.1 0.4]        [1.4 3.2]</span></span>
<span data-line=""><span>[4 5 6]   ×    [0.2 0.5]   =    [3.2 7.7]</span></span>
<span data-line=""><span>               [0.3 0.6]</span></span></code></pre></figure>
<p>Each output entry is a row of <code>X</code> dotted with a column of <code>W</code>. The top-left is <code>1×0.1 + 2×0.2 + 3×0.3 = 1.4</code>: example one, neuron one. The bottom-right is <code>4×0.4 + 5×0.5 + 6×0.6 = 7.7</code>: example two, neuron two. Every example meets every neuron in one operation.</p>
<h2 id="how-much-arithmetic"><a class="heading-anchor" href="#how-much-arithmetic">How much arithmetic</a></h2>
<p>Multiplying an <em>m × k</em> matrix by a <em>k × n</em> matrix takes <em>m × n × k</em> multiplications and about as many additions: <strong>2mnk</strong> floating-point operations.</p>
<p>For a language model, every parameter is used in one multiply and one add for each token processed. So a forward pass costs about <strong>2 × parameters</strong> operations per token. For a 70B-parameter model, that is roughly <strong>140 billion operations per token</strong>. Generating a 500-token answer is 70 trillion.</p>
<p>That volume is only practical because matrix multiplication is the operation hardware has been built around: GPUs and TPUs have dedicated units that multiply small tiles of matrices in a single instruction.</p>
<h2 id="the-catch-reuse"><a class="heading-anchor" href="#the-catch-reuse">The catch: reuse</a></h2>
<p>How fast a matrix multiplication runs depends on how many times each number loaded from memory gets used.</p>
<p>When a language model generates text for a single user, each step processes one token. The "batch" is one row. The layer is a matrix times a <em>vector</em>: every weight is loaded from memory, used for exactly one multiply-add, and discarded. With 16-bit weights that is 2 operations per 2 bytes — <strong>1 operation per byte</strong>.</p>
<p>An H100-class GPU needs about 295 operations per byte to keep its arithmetic units busy (its compute divided by its memory bandwidth). At 1, it is idle almost all the time, waiting for weights to arrive.</p>
<p>Now serve many users at once. With a batch of <em>B</em> tokens, each weight loaded is used <em>B</em> times — once per row:</p>






























<table><thead><tr><th>batch size</th><th>operations per byte</th><th>share of peak compute</th></tr></thead><tbody><tr><td>1</td><td>1</td><td><strong>0.34%</strong></td></tr><tr><td>8</td><td>8</td><td>2.71%</td></tr><tr><td>64</td><td>64</td><td>21.7%</td></tr><tr><td>295</td><td>295</td><td><strong>100%</strong></td></tr></tbody></table>
<p>Up to that point, adding users costs almost nothing extra: the weights are being streamed from memory anyway, and the arithmetic units had spare capacity. This one fact is why inference servers batch requests together, and why the cost per token falls so steeply with traffic.</p>

<h2 id="where-else-it-appears"><a class="heading-anchor" href="#where-else-it-appears">Where else it appears</a></h2>
<p><strong>Training</strong> processes large batches of long sequences, so its matrices are big on every side and it runs close to peak. That is why training throughput numbers look so much better than single-user inference numbers on the same hardware.</p>
<p><strong>Prefill</strong>, the first pass over a prompt, multiplies the weights by every prompt token at once — a tall matrix — and is compute-bound even for one user. <strong>Decode</strong>, one token at a time, is the matrix-times-vector case, bandwidth-bound unless batched.</p>
<p><strong>Attention</strong> contains matrix multiplications of its own: queries times keys to score every pair of positions, and scores times values to mix them. These grow with sequence length rather than with parameter count, which is why long contexts get expensive.</p>
<h2 id="why-the-shapes-are-what-they-are"><a class="heading-anchor" href="#why-the-shapes-are-what-they-are">Why the shapes are what they are</a></h2>
<p>Hardware multiplies matrices in fixed-size tiles — often 16 × 16 or larger. Matrices whose dimensions are multiples of the tile size fill the hardware exactly; awkward sizes waste part of each tile. This is why model widths are numbers like 4,096 and 8,192, head dimensions are 64 or 128, and vocabularies are often padded up to a round multiple.</p>
<h2 id="what-to-take-away"><a class="heading-anchor" href="#what-to-take-away">What to take away</a></h2>
<p>A neural network layer is a matrix multiplication: inputs times weights, every example meeting every neuron at once, at a cost of 2mnk operations. A language model does about 2 × parameters operations per token — 140 billion for a 70B model.</p>
<p>How fast it runs depends on reuse. One token at a time, each weight is used once per load and the GPU reaches 0.34% of its compute. Batch 295 tokens together and the same loads feed the arithmetic fully.
