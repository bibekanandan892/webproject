12:T27fa,<p>Speculative decoding works by proposing several tokens cheaply and checking them all in one pass of the large model. The speedup is just the average number of proposals accepted per pass, so everything comes down to making the proposals better.</p>
<p>EAGLE's answer is to change <strong>what</strong> gets predicted.</p>
<h2 id="why-guessing-tokens-is-hard"><a class="heading-anchor" href="#why-guessing-tokens-is-hard">Why guessing tokens is hard</a></h2>
<p>A drafter that predicts the next token has to predict the outcome of a sample.</p>
<p>The model produces a distribution and one token is drawn from it. If that distribution has 2.1 bits of entropy, there are effectively 4.3 plausible choices — and which one appears is genuinely random. A drafter predicting it is trying to guess a coin flip with four sides.</p>

























<table><thead><tr><th>entropy of the token distribution</th><th>plausible choices to guess among</th></tr></thead><tbody><tr><td>0.5 bits</td><td>1.4</td></tr><tr><td>1.4 bits</td><td>2.6</td></tr><tr><td>2.1 bits</td><td>4.3</td></tr><tr><td>3.2 bits</td><td>9.2</td></tr></tbody></table>
<p>That noise is irreducible. It is not a weakness of the drafter; it is a property of what the drafter was asked to predict.</p>
<h2 id="predicting-the-state-instead"><a class="heading-anchor" href="#predicting-the-state-instead">Predicting the state instead</a></h2>
<p>Before the model produces that distribution, it computes a hidden state — a dense vector near the top of the network. The distribution is derived from it.</p>
<p>That vector is not sampled. It is a deterministic function of the context. So predicting it is a regression problem with a single correct answer, not a guess at a random draw.</p>
<p>It is also smoother. Consecutive hidden states are close together in a way consecutive tokens are not, because the state changes continuously as context accumulates while the token identity jumps around a discrete vocabulary.</p>
<h2 id="the-subtlety-that-makes-it-work"><a class="heading-anchor" href="#the-subtlety-that-makes-it-work">The subtlety that makes it work</a></h2>
<p>There is an obvious objection, and resolving it is the paper's actual contribution.</p>
<p>The next hidden state is not determined by the current one alone. It is:</p>
<pre><code>h(t+1) = f( h(t), x(t+1) )
</code></pre>
<p>where <code>x(t+1)</code> is the token that was sampled. So given only <code>h(t)</code>, the next state is uncertain — and it is uncertain by <strong>exactly the entropy of the sampled token</strong>. The randomness did not disappear; it moved.</p>
<p>The fix is to feed the sampled token back in. The drafter receives both the previous hidden state and the token that was actually drawn, and with both, the next state is determined. No entropy left to guess at.</p>
<p>This is why the method is not simply "predict features instead of tokens". It is <em>predict features conditioned on the token you already know</em> — which is the one framing under which the target has no noise in it.</p>

<h2 id="what-that-buys-precisely"><a class="heading-anchor" href="#what-that-buys-precisely">What that buys, precisely</a></h2>
<p>The speedup is the average accepted tokens per pass. Treating the accept chain as geometric, <code>E = 1/(1 − p)</code>:</p>





























<table><thead><tr><th>tokens per pass</th><th>implied accept rate</th></tr></thead><tbody><tr><td>2.0</td><td>50.0%</td></tr><tr><td>2.5</td><td>60.0%</td></tr><tr><td>3.0</td><td>66.7%</td></tr><tr><td>3.5</td><td><strong>71.4%</strong></td></tr><tr><td>4.0</td><td>75.0%</td></tr></tbody></table>
<p>So moving from token-level drafting at 2.5 tokens per pass to feature-level at 3.5 is an accept rate going from 60.0% to 71.4% — <strong>11.4 percentage points</strong>, producing a <strong>1.40×</strong> speedup on top of what speculative decoding already gave.</p>
<p>That leverage is the thing to notice. Because the chain is geometric, small improvements in accept rate produce large improvements in throughput, and they get larger the higher you already are: 50% → 60% buys 0.5 tokens, while 66.7% → 75% buys 1.0.</p>
<p>Published results put the method at roughly 3 to 4× overall, which is consistent with these accept rates.</p>
<h2 id="spending-the-tree-budget-where-it-pays"><a class="heading-anchor" href="#spending-the-tree-budget-where-it-pays">Spending the tree budget where it pays</a></h2>
<p>The follow-up work changed how candidates are arranged rather than what is predicted.</p>
<p>A <strong>fixed</strong> draft tree has a shape decided in advance — branch twice at every level, say. With 60 nodes that supports about four speculative tokens, and it spends the same number of nodes on parts of the sequence the drafter is certain about as on parts where it is not.</p>
<p>A <strong>dynamic</strong> tree expands where the drafter's confidence is high and stops early where it is low. Same 60-node budget, but the nodes go into depth along the likely continuation rather than into breadth everywhere.</p>

















<table><thead><tr><th></th><th>with 60 nodes</th></tr></thead><tbody><tr><td>fixed, uniform branching</td><td>~4 speculative tokens</td></tr><tr><td>concentrated on the confident path</td><td>considerably deeper on that path</td></tr></tbody></table>
<p>The drafter's own confidence is the signal, and it is free — it was computed anyway.</p>
<h2 id="where-it-ended-up"><a class="heading-anchor" href="#where-it-ended-up">Where it ended up</a></h2>
<p>Two ideas from this line of work are now standard in serving systems.</p>
<p><strong>Draft from the target's internal state.</strong> A drafter that reads the model's hidden representation is both smaller and better aligned than an independent model, because it is predicting the same thing the model is about to do rather than imitating its output.</p>
<p><strong>Shape the draft tree from confidence.</strong> Any fixed shape is spending its budget without looking at the problem.</p>
<h2 id="what-to-take-away"><a class="heading-anchor" href="#what-to-take-away">What to take away</a></h2>
<p>The whole method reduces to choosing a prediction target with no noise in it.</p>
<p>Tokens are sampled, so guessing them means guessing a random draw.
