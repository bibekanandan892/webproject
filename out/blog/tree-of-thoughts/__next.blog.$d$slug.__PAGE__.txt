5:T211c,<p>Chain-of-thought prompting asks a model to reason step by step before answering. It helps a great deal, but it has a structural weakness: the chain is written once, left to right. If step two goes wrong, every step after it builds on the mistake. There is no going back.</p>
<p>Tree of Thoughts treats reasoning as a search instead. At each step the model proposes several possible next thoughts, evaluates them, keeps the promising ones, and expands those further. Dead ends are abandoned. The answer is the best path found through the tree.</p>
<h2 id="the-parts"><a class="heading-anchor" href="#the-parts">The parts</a></h2>
<p>A Tree of Thoughts system needs four decisions:</p>
<ol>
<li><strong>What a "thought" is.</strong> A unit of progress small enough to evaluate — one equation in a maths puzzle, one line of a plan, one paragraph outline.</li>
<li><strong>How to generate candidates.</strong> Sample <em>b</em> different next thoughts from the current state, or ask the model to propose <em>b</em> options in one call.</li>
<li><strong>How to evaluate them.</strong> Ask the model to rate each partial solution — "sure / likely / impossible" — or to vote on which is most promising. Sometimes a program can check directly.</li>
<li><strong>How to search.</strong> Breadth-first, keeping the best <em>k</em> states at each level (a beam), or depth-first with backtracking when a branch is judged hopeless.</li>
</ol>
<h2 id="why-it-helps-the-arithmetic"><a class="heading-anchor" href="#why-it-helps-the-arithmetic">Why it helps: the arithmetic</a></h2>
<p>Suppose a problem needs three steps and the model gets each step right with probability 0.6 when it writes one attempt.</p>
<p><strong>One chain:</strong> all three must be right. <code>0.6³ =</code> <strong>21.6%</strong>.</p>
<p><strong>A tree with 5 candidates per step:</strong> the chance at least one of five candidates is right is <code>1 − 0.4⁵ = 98.98%</code>. If the evaluator always recognises the right one, three steps succeed with probability <code>0.9898³ =</code> <strong>97.0%</strong>.</p>
<p>That is the promise: generate several options at each step, and the search almost always contains a correct path even when any single attempt usually fails.</p>
<h2 id="the-catch-the-judge"><a class="heading-anchor" href="#the-catch-the-judge">The catch: the judge</a></h2>
<p>But the evaluator is the same model, and it is not perfect. If it picks the correct candidate — when one exists — with probability <em>e</em>:</p>






























<table><thead><tr><th>judge accuracy</th><th>per step</th><th>three steps</th></tr></thead><tbody><tr><td>perfect</td><td>0.990</td><td><strong>97.0%</strong></td></tr><tr><td>0.9</td><td>0.891</td><td>70.7%</td></tr><tr><td>0.8</td><td>0.792</td><td><strong>49.6%</strong></td></tr><tr><td>0.7</td><td>0.693</td><td>33.3%</td></tr></tbody></table>
<p>With an 80%-accurate judge, the tree solves the problem about half the time — still more than double the single chain, but nowhere near 97%. The generation side is almost never the bottleneck; recognising the good branch is. Tree of Thoughts works best where evaluation is easier than generation, or where a program can verify partial answers outright.</p>

<h2 id="what-it-costs"><a class="heading-anchor" href="#what-it-costs">What it costs</a></h2>
<p>A beam search keeping <em>k</em> = 5 states, generating <em>b</em> = 5 candidates from each, over <em>d</em> = 3 levels, makes:</p>
<ul>
<li><code>3 × 5 × 5 = 75</code> generation calls</li>
<li><code>75</code> evaluation calls</li>
</ul>
<p><strong>150 model calls</strong> where chain-of-thought made one. Batching and asking for several candidates in one call reduce this, but Tree of Thoughts is fundamentally a way of spending much more inference compute for better answers on hard problems.</p>
<p>The original paper's showcase was the Game of 24 — combine four numbers with arithmetic to make 24 — where GPT-4 with chain-of-thought solved 4% of puzzles and with Tree of Thoughts 74%. That task is close to ideal: each step is one equation, partial states are easy to judge ("can 10 and 14 still make 24? yes"), and errors early are fatal to a single chain.</p>
<h2 id="where-it-fits-now"><a class="heading-anchor" href="#where-it-fits-now">Where it fits now</a></h2>
<p>Reasoning models trained with reinforcement learning do a version of this internally: they explore, notice mistakes and backtrack within one long chain of thought, without an external search harness. For many problems that has replaced explicit Tree of Thoughts.</p>
<p>The explicit version is still useful when:</p>
<ul>
<li><strong>a program can verify partial work</strong> — tests for code, a checker for a puzzle, a solver for constraints;</li>
<li><strong>the search should be inspectable</strong> — every branch and every judgement is logged;</li>
<li><strong>you want to control the budget</strong> — width and depth are parameters, not something the model decides.</li>
</ul>
<h2 id="what-to-take-away"><a class="heading-anchor" href="#what-to-take-away">What to take away</a></h2>
<p>Tree of Thoughts turns reasoning into search: propose several next steps, judge them, keep the best, repeat. Generating five candidates per step makes it very likely the right path exists — 97% versus 21.6% for a single chain on a three-step problem with a perfect judge.</p>
<p>The judge is the limit. At 80% accuracy the same tree solves about half the problems, at roughly 150 calls instead of one.
