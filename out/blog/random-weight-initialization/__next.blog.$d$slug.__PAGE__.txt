5:T2129,<p>Before a neural network trains, its weights need starting values. Zero seems natural — a blank slate. Or any constant. It is one of the few choices in deep learning that is simply wrong, and the reason is worth understanding.</p>
<h2 id="the-symmetry-problem"><a class="heading-anchor" href="#the-symmetry-problem">The symmetry problem</a></h2>
<p>Consider a hidden layer of four neurons, each connected to the same inputs. If all their weights start equal, then:</p>
<ol>
<li><strong>Forward pass:</strong> every neuron computes the same weighted sum of the same inputs, so every neuron outputs the same value.</li>
<li><strong>Backward pass:</strong> every neuron's outgoing weight is the same too, so every neuron receives the same gradient.</li>
<li><strong>Update:</strong> the same gradient, applied to the same weights, gives the same new weights.</li>
</ol>
<p>After the update the neurons are still identical. And so after the next one, and every one after that. Training cannot break the tie, because nothing in the process treats the neurons differently. Four neurons behave as one neuron copied four times.</p>
<h2 id="seeing-it-happen"><a class="heading-anchor" href="#seeing-it-happen">Seeing it happen</a></h2>
<p>I trained the same small network twice on XOR — 2 inputs, 4 sigmoid hidden neurons, 1 output, 5,000 steps, identical in every respect except the starting weights.</p>























<table><thead><tr><th>starting weights</th><th>final loss</th><th>outputs for (0,0) (0,1) (1,0) (1,1)</th><th>difference between hidden neurons</th></tr></thead><tbody><tr><td>all 0.5</td><td>0.1674</td><td>0.018 · 0.653 · 0.653 · <strong>0.655</strong></td><td><strong>0.0</strong></td></tr><tr><td>random in [−1, 1]</td><td><strong>0.0001</strong></td><td>0.010 · 0.990 · 0.990 · 0.013</td><td>9.73</td></tr></tbody></table>
<p>With constant weights, the four hidden neurons ended training <em>exactly</em> identical — a measured difference of zero. The network behaves as if it had a single hidden neuron, and a single neuron cannot represent XOR: it outputs 0.655 for (1, 1), where the answer is 0, and only 0.653 where the answer is 1. Training made what progress one neuron can make and stopped.</p>
<p>With random weights, each neuron started slightly different, received different gradients, and moved in different directions. They specialised — each learning a different boundary — and together solved the problem to two decimal places.</p>

<h2 id="zero-is-worse-than-any-other-constant"><a class="heading-anchor" href="#zero-is-worse-than-any-other-constant">Zero is worse than any other constant</a></h2>
<p>With all weights at zero, it is even worse. Hidden neurons all output the same value (zero with ReLU, 0.5 with sigmoid), and the gradients flowing back through zero outgoing weights are themselves zero for the earlier layers. Depending on the architecture, parts of the network do not learn at all.</p>
<p>Biases are the exception. Starting biases at zero is normal and harmless, because the random weights already break the symmetry.</p>
<h2 id="random-but-not-any-random"><a class="heading-anchor" href="#random-but-not-any-random">Random, but not any random</a></h2>
<p>Randomness breaks symmetry. The <em>scale</em> of the randomness decides whether signals survive the trip through many layers. Too small and activations shrink layer by layer until they vanish; too large and they grow until they overflow — and gradients do the same on the way back.</p>
<p>The standard schemes choose the scale from the layer's size so that each layer roughly preserves the variance of its input:</p>
<ul>
<li><strong>Xavier / Glorot:</strong> standard deviation about √(1 / fan-in), or √(2 / (fan-in + fan-out)). Designed for tanh and sigmoid.</li>
<li><strong>He / Kaiming:</strong> standard deviation √(2 / fan-in). The factor of 2 compensates for ReLU zeroing out half its inputs. The default for ReLU networks.</li>
</ul>
<p>Transformers often use small, fixed-scale normal initialisations with extra down-scaling of the layers that feed residual connections, so that adding many blocks together does not grow the signal.</p>
<h2 id="randomness-has-consequences"><a class="heading-anchor" href="#randomness-has-consequences">Randomness has consequences</a></h2>
<p>Because initialisation is random, two training runs with different random seeds produce different networks — different weights, often slightly different accuracy. Good practice is to report results over several seeds, and to fix the seed when exact reproducibility matters.</p>
<p>Some techniques exploit this. <strong>Ensembles</strong> train the same architecture from several random starts and average their predictions, which is usually more accurate than any single run, precisely because the random starts lead them to different solutions.</p>
<h2 id="what-to-take-away"><a class="heading-anchor" href="#what-to-take-away">What to take away</a></h2>
<p>If all weights start equal, every neuron in a layer computes the same output, receives the same gradient and makes the same update, so they stay identical for ever. A 4-neuron XOR network started at 0.5 finished with its hidden neurons exactly equal and the problem unsolved; started randomly, it solved it.</p>
<p>Random initialisation breaks that symmetry so neurons can specialise.
