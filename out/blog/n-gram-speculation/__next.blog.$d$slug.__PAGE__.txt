5:T1f0a,<p>Speculative decoding speeds up generation by guessing several tokens ahead and having the large model check all the guesses in one pass. Checking is cheap — decode is limited by memory bandwidth, so verifying five tokens costs about the same as producing one. The question is always where the guesses come from.</p>
<p>The usual answer is a small draft model. N-gram speculation needs nothing of the kind. It takes the guesses from text that is already in the context.</p>
<h2 id="the-observation"><a class="heading-anchor" href="#the-observation">The observation</a></h2>
<p>A great deal of what a model writes, it has just read.</p>
<p>Ask it to fix a bug in a 200-line function and the reply is mostly the function, copied, with three lines changed. Ask it to answer from a document and it quotes names, figures and phrases from that document. Ask it to rewrite an email and most of the sentences survive. In all of these, the next few tokens are very often a continuation of something that appears verbatim earlier in the prompt.</p>
<h2 id="the-mechanism"><a class="heading-anchor" href="#the-mechanism">The mechanism</a></h2>
<p>At each step:</p>
<ol>
<li>Take the last <em>n</em> tokens generated — say the last 3.</li>
<li>Search the context for an earlier occurrence of those 3 tokens.</li>
<li>If found, propose the <em>k</em> tokens that followed it there as the draft.</li>
<li>Run the large model once over the draft. Keep the longest prefix it agrees with, plus one token of its own.</li>
<li>If nothing matched, decode one token normally.</li>
</ol>
<p>The lookup is a string search over a few thousand tokens — microseconds. There is no second model to load, train, keep in memory, or keep in sync with the main one.</p>

<h2 id="how-much-it-gains"><a class="heading-anchor" href="#how-much-it-gains">How much it gains</a></h2>
<p>If each drafted token is accepted with probability α, and <em>k</em> are drafted, the expected number of tokens produced per large-model step is:</p>
<p><code>(1 − α^(k+1)) / (1 − α)</code></p>






























<table><thead><tr><th>acceptance α</th><th>k = 4</th><th>k = 8</th></tr></thead><tbody><tr><td>0.3</td><td>1.43</td><td>1.43</td></tr><tr><td>0.5</td><td>1.94</td><td>2.00</td></tr><tr><td>0.7</td><td>2.77</td><td>3.20</td></tr><tr><td>0.9</td><td><strong>4.10</strong></td><td><strong>6.13</strong></td></tr></tbody></table>
<p>At high acceptance, drafting longer pays — 6.13 tokens a step with 8 drafted. At low acceptance it is pointless: past the first couple of guesses, the chain has almost certainly broken.</p>
<p>But that formula only applies on steps where a match was found. The real gain depends on how often the context offers one:</p>























<table><thead><tr><th>workload</th><th>steps with a match</th><th>acceptance</th><th>tokens per step</th></tr></thead><tbody><tr><td>editing code (k = 8)</td><td>70%</td><td>0.9</td><td><strong>4.59</strong></td></tr><tr><td>open-ended chat (k = 8)</td><td>10%</td><td>0.5</td><td>1.10</td></tr></tbody></table>
<p>On a code edit, generation runs more than four times faster. In free conversation, 10% faster. The method is only as good as the overlap between what was read and what is written.</p>
<h2 id="why-it-is-safe-to-leave-on"><a class="heading-anchor" href="#why-it-is-safe-to-leave-on">Why it is safe to leave on</a></h2>
<p>Two properties make n-gram speculation an easy default.</p>
<p><strong>It never changes the output.</strong> Verification accepts a drafted token only if it is the token the large model would have chosen anyway (or, with sampling, accepts in a way that preserves the model's distribution exactly). The text is the same text, produced sooner.</p>
<p><strong>It rarely makes anything slower.</strong> When there is no match, no draft is made and the step is an ordinary step. When a draft is rejected at the first token, the step still produces one token — the large model's own — at the cost of a slightly longer forward pass, which in the bandwidth-bound regime is close to free.</p>
<p>The one case to watch is large batches. When a server is already processing many sequences per step, it is no longer purely bandwidth-bound, and verifying 8 extra tokens per sequence is real compute. Serving systems typically reduce <em>k</em> or switch speculation off as batch size grows.</p>
<h2 id="compared-with-a-draft-model"><a class="heading-anchor" href="#compared-with-a-draft-model">Compared with a draft model</a></h2>
<p>A trained draft model guesses well on any text, including text that has never appeared in the context. N-gram lookup guesses perfectly on repeated text and not at all on new text.</p>
<p>That makes them complementary rather than competing. Some systems try the n-gram lookup first and fall back to the draft model when it finds nothing — the lookup is so cheap that trying it costs nothing.</p>
<h2 id="what-to-take-away"><a class="heading-anchor" href="#what-to-take-away">What to take away</a></h2>
<p>N-gram speculation drafts tokens by finding the last few generated tokens earlier in the context and proposing what came after them. It needs no extra model, never changes the output, and costs almost nothing when it misses.</p>
<p>Its speed-up is set entirely by how much of the output is copied from the input: 4.59 tokens per step when editing code, 1.10 in open chat.
