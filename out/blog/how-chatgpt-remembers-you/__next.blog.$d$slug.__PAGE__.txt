5:T1e90,<p>Tell ChatGPT you are vegetarian, and a week later in a new conversation it suggests vegetarian recipes without being asked. It feels like the model learned something about you.</p>
<p>It did not. The model's weights do not change when you talk to it; they are the same for every user. A language model also has no state between requests — each one starts from nothing but the text it is given. Everything that feels like memory is the application putting the right text into the prompt before the model sees your message.</p>
<p>OpenAI describes two kinds of memory in ChatGPT, and they work differently.</p>
<h2 id="1-saved-memories"><a class="heading-anchor" href="#1-saved-memories">1. Saved memories</a></h2>
<p>These are short facts the assistant decided — or you asked it — to keep: <em>"Is vegetarian." "Works as a data engineer." "Prefers answers in British English." "Has a dog called Biscuit."</em></p>
<p>When something in a conversation looks worth remembering, the assistant can call a memory tool that writes a new entry, much like any other tool call. You can see the list, edit it and delete from it in settings. And at the start of each conversation, the saved list is included in the model's context, typically as part of the system-level instructions, so every reply is written with those facts in view.</p>
<p>Because the list is injected into every conversation, it has to stay small. Fifty facts at around 20 tokens each is about <strong>1,000 tokens</strong> added to every request. A moderate user sending 30 messages a day sends that block 30 times — <strong>30,000 tokens a day</strong> of the same text. Prompt caching makes that cheaper, but the cost is why memories are stored as terse facts and why the list has a capacity limit.</p>
<h2 id="2-referencing-chat-history"><a class="heading-anchor" href="#2-referencing-chat-history">2. Referencing chat history</a></h2>
<p>The second kind uses your past conversations directly. Instead of a short curated list, the system can draw on what you discussed before — that you were planning a trip to Japan, that you were debugging a particular service — even if nobody explicitly saved it.</p>
<p>The exact implementation is not public, but the shape of any such system is retrieval: past conversations are summarised and indexed, and when you write a new message, the most relevant pieces are found and added to the context alongside the saved memories. It is RAG where the documents are your own chat history.</p>
<p>That brings RAG's usual trade-off. Retrieve 5 snippets of which 3 are relevant, and 60% of what was added helps; retrieve 10 with the same 3 relevant, and 30% does. Irrelevant past context is not harmless — it can steer a reply toward a topic you have moved on from.</p>

<h2 id="what-follows-from-memory-is-text-in-the-prompt"><a class="heading-anchor" href="#what-follows-from-memory-is-text-in-the-prompt">What follows from "memory is text in the prompt"</a></h2>
<p><strong>It can be wrong or stale.</strong> A saved fact is true when written. If you stop being vegetarian and never say so, the memory keeps steering suggestions. Good memory systems update or delete entries when new information contradicts them, but they can only do that when the contradiction is visible in a conversation.</p>
<p><strong>It can be seen and controlled.</strong> Because memories are text, they can be shown to you, edited and deleted — something impossible if they lived inside model weights. Temporary or incognito chats simply skip the injection and the saving.</p>
<p><strong>It shapes every answer.</strong> A remembered preference is always in context, so it influences replies even when it should not — the vegetarian fact surfacing in a question about the history of farming. Systems mitigate this by instructing the model to use memories only when relevant.</p>
<p><strong>It does not make the model better at anything.</strong> Memory personalises; it does not teach. If the model gets something wrong for you, remembering your correction may help in your future chats but changes nothing for anyone else.</p>
<h2 id="how-this-compares-with-agent-memory-in-general"><a class="heading-anchor" href="#how-this-compares-with-agent-memory-in-general">How this compares with agent memory in general</a></h2>
<p>ChatGPT's design is a specific, consumer-facing instance of the general agent-memory stack: a small <strong>always-included profile</strong> (saved memories), plus <strong>retrieved long-term memory</strong> (past chats), plus the <strong>working memory</strong> of the current conversation. Agents built for other tasks use the same layers with different contents — a project's conventions instead of a diet, a ticket history instead of a holiday plan.</p>
<h2 id="what-to-take-away"><a class="heading-anchor" href="#what-to-take-away">What to take away</a></h2>
<p>ChatGPT does not learn from you; its weights are unchanged. It remembers by placing text in the prompt: a compact list of saved facts that rides along with every message — about 1,000 tokens each time — and snippets retrieved from your past conversations when they look relevant.</p>
<p>That makes memory visible, editable and deletable, and also means it can be stale, can intrude where it is not wanted, and costs tokens on every request.
