11:T34a8,<p>In cross attention the queries come from one sequence and the keys and values come from another.</p>
<p>That is the entire definition, and everything interesting about it follows from that one asymmetry.</p>
<h2 id="what-it-is-for"><a class="heading-anchor" href="#what-it-is-for">What it is for</a></h2>
<p>Some tasks have two sequences, not one. Translating means an input sentence and an output sentence. Describing an image means a picture and a caption. Transcribing means audio and text.</p>
<p>The output has to be built while consulting the input, and the two are not the same length and do not line up position by position. Something has to let each output position look at whichever parts of the input matter to it.</p>
<h2 id="reading-a-different-sequence"><a class="heading-anchor" href="#reading-a-different-sequence">Reading a different sequence</a></h2>
<p>Encode the source once. From it, build keys — what each source token offers — and values — what each contributes.</p>
<p>Then, at each output position, form a query from what has been generated so far and compare it against every source key. Softmax the scores, apply them to the values, and the result is a summary of the source, weighted for this particular output position.</p>

<p>Nothing told the model which source token corresponds to which output position. The alignment is an outcome of what each query happens to match, and it is learned.</p>
<h2 id="two-consequences-worth-naming"><a class="heading-anchor" href="#two-consequences-worth-naming">Two consequences worth naming</a></h2>
<p><strong>The matrix is rectangular.</strong> Two output positions against five source tokens is a 2×5 matrix. Within one sequence, attention is always square — every token against every token — which is why masking makes sense there: you can hide the upper triangle.</p>
<p>There is no triangle here. The axes are different sequences, and the whole source already exists before generation starts, so there is nothing to hide. Cross attention is never masked, and that is not a design choice but a consequence of the shape.</p>
<p><strong>The keys and values are built once.</strong> They come from the source, which does not change while the output is generated. So they are computed once and reused at every output step.</p>

















<table><thead><tr><th></th><th>token projections</th></tr></thead><tbody><tr><td>rebuilding K and V at each of 60 output steps</td><td>2,400</td></tr><tr><td>building them once from 40 source tokens</td><td><strong>40</strong></td></tr></tbody></table>
<p>Sixty times fewer, and the factor is exactly the number of tokens generated. The longer the output, the more that one property is worth.</p>
<h2 id="where-it-shows-up"><a class="heading-anchor" href="#where-it-shows-up">Where it shows up</a></h2>
<p><strong>Encoder-decoder models.</strong> The original use: an encoder reads the input, and every decoder layer has a cross-attention step that consults it. Translation, summarisation, question answering over a passage.</p>
<p><strong>Image generation from text.</strong> The image being denoised carries the queries; the encoded prompt supplies keys and values. Each region of the image attends to whichever words are relevant to it, which is how "a red door" puts red on the door and not on the wall.</p>
<p><strong>Speech to text.</strong> The decoder generates text while attending over encoded audio frames.</p>
<p>The pattern generalises past sequences of words entirely. Any time two different things need to be related — and one of them is being produced while the other is fixed — this is the mechanism.</p>
<h2 id="the-short-version"><a class="heading-anchor" href="#the-short-version">The short version</a></h2>
<ul>
<li>Queries come from one sequence; keys and values come from another.</li>
<li>The formula is unchanged from attention within a single sequence; only where the inputs come from differs.</li>
<li>Each output position gets its own weighting over the whole source.</li>
<li>The matrix is rectangular, so there is no triangle to mask — and nothing to hide, since the source is fully known.</li>
<li>Keys and values are built once from the source and reused for every output token: 60× fewer projections on a 60-token output.</li>
<li>Alignment between the two sequences is learned, never specified.</li>
<li>It is what connects an encoder to a decoder, a prompt to an image, and audio to a transcript.</li>
