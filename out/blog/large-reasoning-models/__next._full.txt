11:T2686,<p>An ordinary language model answers immediately. The first token of its reply is produced straight after the question, and everything follows from there.</p>
<p>A reasoning model does not. It first generates a long stretch of working — laying the problem out, computing, checking itself, sometimes going back — and only then writes the answer.</p>
<p>That working is made of ordinary tokens. It is generated exactly the way the answer is, and it is billed exactly the way the answer is.</p>
<h2 id="what-the-working-looks-like"><a class="heading-anchor" href="#what-the-working-looks-like">What the working looks like</a></h2>
<p><em>A van leaves at 08:20 averaging 54 km/h. A second leaves the same place at 09:05 averaging 72 km/h. When does the second catch the first?</em></p>
<p>The trace runs something like this:</p>
<blockquote>
<p>The second leaves 45 minutes later, so the first has a head start. Head start = 45 × 54 = 2,430 km.</p>
<p>That cannot be right — 2,430 km in 45 minutes. The 45 is in minutes and the speed is per hour. 45 minutes is 0.75 h, so the head start is 0.75 × 54 = <strong>40.5 km</strong>.</p>
<p>The second gains at 72 − 54 = 18 km/h. Closing 40.5 km takes 40.5 ÷ 18 = <strong>2.25 h</strong>.</p>
<p>2.25 h after 09:05 is <strong>11:20</strong>.</p>
<p>Check: the second travels 72 × 2.25 = 162 km. The first has been going from 08:20 to 11:20, which is 3 h, so 54 × 3 = 162 km. Same. ✓</p>
</blockquote>
<p>Three behaviours in there, and they are the point.</p>
<p>It <strong>broke the problem down</strong> rather than reaching for the answer. It <strong>caught its own mistake</strong> — the units slip in the first line is exactly the error a model answering directly would have carried through to a confident wrong answer. And it <strong>checked the result by a different route</strong>, computing the same distance two ways.</p>
<p>None of that is reasoning in any deep sense. It is a learned habit of producing text that has those shapes, and the habit is worth a great deal on problems where a single slip ruins the answer.</p>
<h2 id="where-the-ability-comes-from"><a class="heading-anchor" href="#where-the-ability-comes-from">Where the ability comes from</a></h2>
<p>Not from the pre-training, and not from instruction tuning. From a third stage that only works on problems whose answers can be <strong>checked automatically</strong>.</p>
<p>Take a hard problem with a known answer. Have the model produce many attempts in parallel — a few dozen. Run each one's final answer through a checker: is the number right, do the unit tests pass, does the proof hold. Score each attempt against how the rest of the group did, then reinforce the patterns in the ones that worked.</p>
<p>The checker is what makes this possible and what limits it. Nobody has to grade the reasoning — only the final answer, and only in domains where correctness is mechanically decidable. Which is why reasoning models are strongest at maths, code and formal logic, and much less transformed on questions where nothing can be automatically verified.</p>
<p>What gets learned is not the answers. It is the habits: decompose, check units, verify by a second method, notice when a number is absurd.</p>

<p>Accuracy on hard problems rises with the amount of working — more attempts, longer traces, or both. That is a real and repeatable effect, and it is what makes these models worth having.</p>
<p>The cost is straightforwardly proportional. At $12 per million output tokens and around 80 tokens a second:</p>

<p>Two things follow.</p>
<p>The user sees a 200-token answer in every row. Nothing on screen indicates whether it cost <span class="katex"><span class="katex-mathml"><math xmlns="http://www.w3.org/1998/Math/MathML"><semantics><mrow><mn>0.0024</mn><mi>o</mi><mi>r</mi></mrow><annotation encoding="application/x-tex">0.0024 or </annotation></semantics></math></span><span class="katex-html" aria-hidden="true"><span class="base"><span class="strut" style="height:0.6444em;"></span><span class="mord">0.0024</span><span class="mord mathnormal" style="margin-right:0.0278em;">or</span></span></span></span>0.40, which makes reasoning spend easy to lose track of — it is invisible in the output and only appears on the bill.</p>
<p>And the latency is not a queue or a slow server. Generating 32,000 tokens takes as long as generating 32,000 tokens.</p>
<h2 id="using-them-well"><a class="heading-anchor" href="#using-them-well">Using them well</a></h2>
<p><strong>Do not use one for easy work.</strong> A summary or a reformat gains nothing from a thinking trace and pays the full multiple for it. The gap only appears on problems with enough steps for a slip to matter.</p>
<p><strong>Set a budget.</strong> Uncapped thinking on production traffic makes costs unpredictable, because the model decides how long to think. A fixed ceiling — a few thousand tokens normally, more for known-hard requests — makes the bill bounded.</p>
<p><strong>Do not tell it to think step by step.</strong> That instruction exists to induce working in models that were not trained to produce it. A model already trained to think does it anyway, and being told again mostly disrupts the pattern it learned.</p>
<p><strong>Never show the trace as the answer.</strong> It contains abandoned approaches and corrected mistakes — the 2,430 km line above is in there. It is working, not output.</p>
<h2 id="the-short-version"><a class="heading-anchor" href="#the-short-version">The short version</a></h2>
<ul>
<li>A reasoning model generates a long trace of working before its answer.</li>
<li>The trace is made of ordinary tokens: generated, billed and timed like any others.</li>
<li>Its useful habits are decomposition, self-correction, and verifying by a second method.</li>
<li>It is trained by generating many attempts to problems with checkable answers and reinforcing the ones that come out right.</li>
<li>That is why the gains concentrate in maths, code and logic — the domains a checker can grade.</li>
<li>Accuracy rises with thinking, and so does cost: 8,192 thinking tokens is 42× a direct answer.</li>
<li>The user sees the same short answer either way, which is what makes the spend easy to miss.</li>
